# 11 — Roadmap & Agent Work Packages

Phases are sequential; work packages (WP) within a phase parallelize across agents. Every WP lists acceptance criteria (AC) — a WP is done when ACs pass in CI, not before. Conventions in [CLAUDE.md](../CLAUDE.md).

**Status 2026-07-31: Phase 0 is COMPLETE** (see [docs/notes/phase-0-review.md](notes/phase-0-review.md)) **and Phase 1 is feature-complete: WP-1.0a, 1.1, 1.2, 1.3, 1.4, 1.4b, 1.5, 1.6a, 1.6b, 1.7, 1.8 and 1.9 are all merged** (PRs #11–24) — see [phase-1-midpoint.md](notes/phase-1-midpoint.md) for the mid-phase review and **[phase-1-review.md](notes/phase-1-review.md) for the end-of-phase review**. **Dependency rules for agents:** (1) never start a module WP before WP-0.8 is green; (2) numbered tracks 7–10 (migration, compliance, portability, topology) are *cross-phase tracks* — their WPs state which phase they land with; (3) within a phase, WPs are parallel unless one's AC references another's output; (4) when in doubt, the phase number in this section wins over any per-doc build-plan note.
**Superseded WPs (do not build):** WP-4.6 → WP-7.4 · WP-5.5 → WP-7.7 · WP-5.7 → WP-8.2.

## Phase 1 — Ledger + first vertical slice (usable accounting MVP)
- **WP-1.0a Metadata DDL evolution** (closes the WP-0.5 create-only gap, blocks any overlay that alters an existing object): schema diffing, additive ALTER planning (expand-only within a version, per expand→migrate→contract discipline), plan preview + apply tracked in object_schema_migrations, both dialects. AC: add-field/widen-type overlay on an existing populated object round-trips on Postgres AND SQLite with data intact; destructive diffs are refused with a clear error.
- **WP-1.1 Money & currency core:** money type (minor units), decimal policy, currency registry, FX rate store + ECB provider. AC: property tests on rounding/allocation (no lost cents in splits).
- **WP-1.2 Ledger module:** accounts, journal entries, periods, posting pipeline with storage-enforced invariants. **First task: extend the metadata engine with event-sourced object support** (deferred from WP-0.5 — CRUD-only today). AC: unbalanced/closed-period/mutation attempts all rejected at storage layer; trial balance projection matches event fold under fuzzing; **full DB role separation lands here** (docs/19 layer 3, deferred from WP-0.8 per kernel/integrity/grants.go) — app role provably cannot write protected tables outside pipeline-owned paths.
- **WP-1.3 Tax engine v1:** jurisdictions, rules, effective-dated rates as data; document tax calculation; US state + EU VAT seed packs. AC: golden-file test suite of tax scenarios.
- **WP-1.4 Invoicing/AR module** (per 10-MODULES.md M2, minus payments/dunning). AC: invoice lifecycle e2e — draft → post → GL entries correct → PDF renders.
- **WP-1.4b Boot assembly + action surface** (added by the [phase-1 midpoint review](notes/phase-1-midpoint.md); blocks WP-1.5): everything built in 1.0a–1.4 is currently test-only — `lasterp serve` still boots the WP-0.1 hello-world mux with no DB, no authenticator, no modules. This WP wires the real product: server config (DSN, listen addr), migrations on boot, module `Register()` per capability state, kernel/identity as the gateway `Authenticator`, capability checker wired; gateway grows **action endpoints** (post invoice, reverse entry, close/reopen period, tax/FX rate admin, capability enable/disable — metadata-declared first, hand-extended second) and read routes for event-sourced objects (JournalEntry). The tax/FX reference-data write **authz seam** (deferred from 1.1/1.3 as "no API surface yet") MUST land here — that deferral is only safe while the surface doesn't exist. AC: cold `lasterp serve` against fresh Postgres AND SQLite boots migrated; full invoice lifecycle (draft → post → GL → PDF) driven over HTTP with authn + idempotency keys; OpenAPI documents the action routes; unauthorized tax-rate write via API rejected.
- **WP-1.5 Web client v1:** metadata-rendered list/form/detail, auth, navigation, LastERP UI kit foundations. Adds the session routes (`POST /api/v1/sessions` + refresh — the only `Public` routes, see [decisions §4](notes/WP-1.5-decisions.md)), the `GET /api/v1/meta/objects` schema surface the renderer reads, static serving of the built bundle, and `lasterp bootstrap` (nothing could create the first tenant/user before it). AC: Playwright e2e on invoice lifecycle; p95 budget smoke; axe-core a11y gate live from here on (docs/17).
- **WP-1.6 Reports v1 + metrics layer** — **split into two PRs** (see [decisions](notes/WP-1.6-decisions.md)): **PR-A (WP-1.6a) AR receipts + settlement** — the invariant-bearing half, landing the new **INV-F8** (settlement never exceeds the document it settles); **PR-B (WP-1.6b) reports + metrics + export** — new read-only `modules/reporting` (trial balance, P&L, balance sheet, AR aging), metrics layer v1, CSV/XLSX export, drill-down via source ids; reconciled against the event-fold oracle. Also lands the `ledger_balance_cursor` read-time projection catch-up, without which the projection was empty in a running system. Settlement state is *derived* from receipts, never written onto the posted invoice (INV-F2). Amended per [21-REPORTING-DASHBOARDS.md](21-REPORTING-DASHBOARDS.md): trial balance, P&L, balance sheet, AR aging from projections; CSV/XLSX export; metrics layer v1 + drill-down. **Includes minimal AR receipt recording** (payment → GL via declared template + invoice paid/partial status): no other WP owns it, aging is degenerate without payment-reduced balances, and M1 ("keep books") implies booking customer payments — full payment matching/dunning stays in Phase 4 banking. AC: report/metric totals reconcile with event-fold oracle; permission-leak suite green; recorded receipt reduces AR aging and flips invoice status.
- **WP-1.8 Role dashboard packs v1** (CEO/CFO/AR live + a gated AP pack, KPI cards with mandatory comparisons — docs/21): embedded YAML packs, permission-filtered rendering, and the **period-aware metrics layer** the comparisons needed (metric `grain` = flow/stock, folded on the entry's fiscal period; ledger metrics were all-time, so every delta would have been zero). Adds `lasterp demo` to seed a real book through the posting pipeline. Decisions: [WP-1.8-decisions.md](notes/WP-1.8-decisions.md). AC: fresh tenant shows live role dashboard from seed data.
- **WP-1.7 Translation packs + localized documents** (docs/17): versioned JSON packs (server document strings + client UI strings) with CI-enforced completeness, the first non-English pack (**German**), `localized: true` metadata fields carrying per-locale values in the `custom_fields` blob, per-locale invoice line text frozen into the document, and PDF rendering in the counterparty's language (`Contact.locale` → `Invoice.locale`, WinAnsi encoding, exact money rendering — the old float divide broke INV-F4 past 2^53). Decisions: [WP-1.7-decisions.md](notes/WP-1.7-decisions.md). AC: invoice e2e fully localized incl. PDF in first non-English locale.
- **WP-1.9 OIDC AuthProvider** (deferred from WP-0.3; required before any non-dogfood user): second AuthProvider implementation behind the existing interface; **[ADR-019](adr/ADR-019-jose.md) selects the JOSE library** (per the no-new-deps rule) — and selects *none*: a stdlib verifier with a closed algorithm allowlist. Authorization-code flow with PKCE, deployment-level provider configuration, and link-on-first-use to an existing user (the IdP authenticates, it never provisions or authorizes). Decisions: [WP-1.9-decisions.md](notes/WP-1.9-decisions.md). AC: OIDC login e2e against a test IdP (Keycloak container); session/device semantics identical to password path; authz property tests unchanged.
- **WP-1.10 Phase-1 review follow-ups** ([phase-1-review.md](notes/phase-1-review.md) P1 items; mirrors WP-0.10 for Phase 0). Everything here is perimeter work the feature WPs left behind, and all of it gates safe dogfooding rather than correctness:
  (a) **supply chain** — bump `golang.org/x/text` (GO-2026-5970 is *reachable* via `storage.Open`), `golang.org/x/crypto`, `modernc.org/sqlite`; add `govulncheck` + `pnpm audit` CI jobs and SBOM-per-release, all three specified in docs/08 and none built — the stale deps are the symptom, the missing gate is the defect;
  (b) **toolchain** — Go 1.26.4 → 1.26.5 across `go.mod`, five `ci.yml` steps, docs/02 and ADR-001 (ADR-001's own "within 2 weeks" rule), and restore the `toolchain` directive ADR-001 specifies and `go.mod` lacks;
  (c) **web hardening** — CSP, `X-Content-Type-Options: nosniff`, HSTS, `X-Frame-Options`, `Referrer-Policy` (docs/08 lists CSP and HSTS as shipped; nothing sets any header today), plus `http.Server` read/write/idle timeouts and `Shutdown(ctx)` instead of `Close()`;
  (d) **role separation becomes deployable** — `EnforceAppendOnlyGrants`/`EnforceLedgerPipelineGrants` are called only from tests, so INV-F5's storage-layer claim is true in CI and false in production. Land a first-class path (CLI subcommand + Helm/compose values + docs) that provisions a restricted app role and applies the grants, and a `lasterp doctor`-style check that reports when a deployment is running unseparated;
  (e) **one authentication path** — `PasswordTOTPProvider` is dead in production (`internal/app/sessions.go` reimplements it inline, with a timing-equalizer the provider lacks); converge on the `AuthProvider` interface or delete it, but stop maintaining two copies of an auth decision;
  (f) **lint floor** — enable `gosec`, `rowserrcheck`, `sqlclosecheck`, `errorlint`, `bodyclose`, `nilerr` with the known false positives annotated; fix the real findings (`reporting/card.go` swallowing every prior-period error including real DB failures, unsanitized request path into `log.Printf`);
  (g) nits: tax/FX reference-data **read** API (WP-1.4b deferred the read half), `MEMORY.md` into `.gitignore`, `RefreshSession`'s doc comment.
  AC: `govulncheck ./...` and `pnpm audit` clean (or waivered in-repo with an expiry) and both failing CI on regression; header assertions in the e2e suite; a Postgres e2e that boots serving as a restricted role and proves a direct `INSERT INTO events` is refused (42501) through the *shipped* deployment path, not a test fixture; exactly one code path issues a password session; expanded lint set green.
- **WP-1.11 Metadata field validation + schema descriptors** (closes the ADR-006 gap WP-1.6 §5 flagged as "the one finding that outlives this WP"; blocks **WP-2.2**, which generates client replica schemas from the same metadata). `CRUD.validate` checks required-ness and nothing else — no type validation, and `enum` has no options list at all, so `POST /api/v1/account {"type":"banana"}` is accepted into the chart of accounts today (reports surface it in an explicit `unclassified` bucket rather than dropping it, which is why it has not bitten). Adds: `Options` on enum fields, per-`FieldType` value validation on create/update, the overlay semantics for both (an overlay may narrow an option set, never widen it — the ADR-006 permission-floor rule applied to data), a plan for existing out-of-set rows, and the UI descriptors WP-1.5 §2 deferred (field order, grouping, widget overrides) since they are the same schema surface. AC: every enum field in a shipped module declares its options and an out-of-set write is refused on both dialects; a wrong-typed value for each `FieldType` is refused; an overlay narrowing an option set is accepted and one widening it is refused; the renderer drives field order from the schema rather than declaration order.
- **WP-1.12 TOTP enrollment** (makes M1's "password+TOTP" true — `ValidateTOTP`/`EnableTOTP` exist and the login route accepts a code, but nothing lets a user turn it on, so the level actually available is password-only). Enrollment endpoint issuing an `otpauth://` URI + QR, confirm-before-enable, single-use recovery codes stored hashed, disable-with-reauthentication, and the account-settings screen for all of it. Every transition audited (INV-T4). AC: enroll → confirm → sign in with a code → consume a recovery code → disable, driven over HTTP and in the Playwright suite; a recovery code cannot be reused; enrollment and disablement appear in `audit_log`.
- **Milestone M1: "a small firm can invoice and keep books"** — dogfood tenant live (password+TOTP acceptable for dogfood; OIDC before external users). Gated on WP-1.10 (a reachable CVE and an unhardened browser surface are not dogfood-ready) and WP-1.12 (without it the "+TOTP" in this line is aspirational).

## Phase 3 — Extensibility & AI
- **WP-3.0 Secrets vault** (specified in docs/08, referenced by docs/20, never scheduled — blocks WP-3.1's capability-gated `secrets.get`, and until it exists every credential the product needs has to live in deployment environment variables). Kernel envelope encryption with a pluggable key source (KMS for cloud, age file for self-host, per docs/08), tenant-scoped secret storage, read paths that never surface plaintext in logs, events, exports or plugin memory, and rotation. **Unblocks per-tenant OIDC provider configuration**, which WP-1.9 §2 deferred precisely because storing an OAuth client secret at rest had nowhere safe to go (see [WP-1.9-decisions.md](notes/WP-1.9-decisions.md) §2). AC: a secret round-trips without plaintext at rest; a tenant cannot read another's secret (INV-T1); reading a secret is authorized and audited (INV-T2/T4); a plugin without `secrets.get` cannot reach one (INV-X1, lands with WP-3.1); key rotation re-wraps without re-encrypting the payloads; grep the logs, event store and an export of a tenant carrying a known secret and find no plaintext.
- **WP-3.1 Plugin host:** wazero + Extism integration, manifest/capabilities, hook points, resource limits, circuit breakers. AC: hostile-plugin test suite (infinite loop, memory bomb, exfiltration attempt) all contained.
